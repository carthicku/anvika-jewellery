# Database Schema

PostgreSQL 17. Managed by Alembic migrations in `backend/alembic/versions/`.
The ER diagram is in [ER_DIAGRAM.md](ER_DIAGRAM.md).

## Conventions

| Topic | Rule |
|-------|------|
| Primary keys | `UUID` (`uuid4`, generated by the application) for every table except pure join tables and key/value tables. |
| Timestamps | `timestamptz`, always UTC. Most tables have `created_at` and `updated_at` (server default `now()`). |
| Money | `NUMERIC(12,2)` in rupees + an explicit `currency CHAR(3)` (`'INR'`) on records that hold money. Razorpay amounts (paise) are `BIGINT` with the suffix `_paise`. |
| Weights | `NUMERIC(10,3)` grams (`_g`), carats `NUMERIC(8,3)` (`_ct`). |
| Percentages | `NUMERIC(6,3)` e.g. `3.000` = 3%. |
| Enums | Stored as `VARCHAR` with a `CHECK` constraint (simpler migrations than native PG enums). Allowed values live in `app/models/enums.py`. |
| Deletion | Orders, payments, movements and audit logs are never deleted. Products are archived (`status='archived'`), not deleted, once ordered. |
| Naming | snake_case plural table names; constraint names follow the SQLAlchemy naming convention in `app/models/base.py`. |
| Secrets | Passwords → Argon2id hash. Session/reset/verify/cart/guest-order tokens → SHA-256 hash only. No card data is ever stored. |

## Tables by domain

### Identity & access
| Table | Purpose | Key columns / constraints |
|-------|---------|---------------------------|
| `users` | Customers, staff, admins | `email` unique (stored lower-case), `password_hash`, `full_name`, `phone`, `role` ∈ {customer, staff, admin}, `is_active`, `email_verified_at`, `last_login_at`, `mfa_secret_encrypted` (nullable, Phase 7) |
| `user_sessions` | One row per signed-in device | `user_id` FK, `refresh_token_hash` unique, `previous_refresh_token_hash`, `user_agent`, `ip_address`, `expires_at`, `last_used_at`, `revoked_at` |
| `user_tokens` | Email-verification and password-reset tokens | `user_id` FK, `purpose` ∈ {email_verify, password_reset}, `token_hash` unique, `expires_at`, `used_at` |
| `addresses` | Customer address book | `user_id` FK, `full_name`, `phone`, `line1`, `line2`, `landmark`, `city`, `state`, `pincode CHAR(6)` (CHECK `^[1-9][0-9]{5}$`), `country='IN'`, `is_default_shipping`, `is_default_billing` |

Roles and permissions: the `role` column plus a fixed role→permission map in
`app/core/permissions.py` (see [AUTHENTICATION.md](AUTHENTICATION.md)). A separate permissions table
was deliberately not created, so that no data edit can grant new powers.

### Catalogue
| Table | Purpose | Key columns / constraints |
|-------|---------|---------------------------|
| `categories` | Rings, earrings, necklaces… (one level of nesting allowed) | `parent_id` self-FK, `name`, `slug` unique, `description`, `image_url`, `sort_order`, `is_active`, `seo_title`, `seo_description` |
| `collections` | Curated groupings (Bridal, Everyday…) | `slug` unique, `name`, `description`, `hero_image_url`, `is_active`, `is_featured`, `sort_order`, SEO fields |
| `collection_products` | M:N | PK (`collection_id`, `product_id`), `sort_order` |
| `products` | A design | `slug` unique, `name`, `category_id` FK, `status` ∈ {draft, active, archived}, `metal_colour` ∈ {yellow, white, rose, two_tone}, `purity` ∈ {24K, 22K, 18K, 14K}, `pricing_model` ∈ {fixed, weight_based}, `making_charge_type` ∈ {per_gram, percent, flat, none}, `making_charge_value`, `wastage_percent` (nullable), `description`, `stone_details`, `hallmark_details`, `certification_details`, `care_instructions`, `return_eligible`, `exchange_eligible`, `return_window_days`, `is_featured`, `is_bestseller`, `is_sample`, SEO fields, `published_at`, `search_vector` (generated `tsvector`, GIN index) |
| `product_variants` | A purchasable SKU (e.g. ring size 12) | `product_id` FK, `sku` unique, `label`, `size`, `gross_weight_g`, `net_gold_weight_g`, `stone_weight_ct`, `stone_value`, `other_charges`, `other_charges_label`, `fixed_price` (required when product is `fixed`), `huid` (nullable, per piece), `is_default`, `is_active`, `sort_order` |
| `product_images` | Gallery | `product_id` FK, `storage_key`, `url`, `alt_text`, `width`, `height`, `sort_order`, `is_placeholder` |
| `product_attributes` | Filterable key/value attributes | `product_id` FK, `key` (e.g. `occasion`, `style`), `value`; unique (`product_id`,`key`,`value`); index (`key`,`value`) |
| `product_reviews` | Customer reviews (moderated) | `product_id` FK, `user_id` FK, `order_item_id` FK (verified purchase), `rating` CHECK 1–5, `title`, `body`, `status` ∈ {pending, approved, rejected}; unique (`user_id`,`product_id`) |

### Pricing
| Table | Purpose | Key columns / constraints |
|-------|---------|---------------------------|
| `gold_rates` | Append-only rate history | `purity`, `rate_per_gram NUMERIC(12,2)` CHECK > 0, `currency`, `effective_from`, `source_note` (required), `created_by` FK users; index (`purity`, `effective_from DESC`) |
| `discounts` | Automatic promotions | `name`, `kind` ∈ {percent_off_making, percent_off_price, flat_off_price}, `value`, `scope` ∈ {all, category, collection, product}, `scope_id`, `starts_at`, `ends_at`, `is_active` |
| `coupons` | Code-based offers | `code` unique (upper-case), `kind` ∈ {percent, flat}, `value`, `max_discount_amount`, `min_order_amount`, `starts_at`, `ends_at`, `usage_limit_total`, `usage_limit_per_customer`, `is_active` |
| `coupon_redemptions` | One per order using a coupon | `coupon_id`, `order_id` unique, `user_id`, `email`, `amount`, `status` ∈ {reserved, redeemed, released} |
| `store_settings` | Key/value configuration (tax rates, announcement, contact placeholders, payment window) | `key` PK, `value JSONB`, `updated_by`, `updated_at` |

### Inventory
| Table | Purpose | Key columns / constraints |
|-------|---------|---------------------------|
| `inventory_levels` | Current stock per variant | `variant_id` PK/FK, `on_hand`, `reserved`, `low_stock_threshold`; CHECK `on_hand >= 0 AND reserved >= 0 AND reserved <= on_hand` |
| `inventory_movements` | Append-only ledger | `variant_id`, `delta_on_hand`, `delta_reserved`, `reason` ∈ {initial, adjustment, reservation, reservation_release, sale, cancellation_restock, return_restock}, `order_id`, `actor_user_id`, `note`, `created_at` |
| `inventory_reservations` | Stock held for a pending order | `order_id`, `variant_id`, `quantity` CHECK > 0, `status` ∈ {active, committed, released}, `expires_at` |

### Cart & wishlist
| Table | Purpose | Key columns / constraints |
|-------|---------|---------------------------|
| `carts` | Guest or customer cart | `user_id` (nullable), `token_hash` unique (guest cookie), `coupon_code`, `status` ∈ {active, converted, merged, abandoned}; partial unique index: one `active` cart per user |
| `cart_items` | Lines | `cart_id`, `variant_id`, `quantity` CHECK 1–10, `accepted_unit_price` (the price the customer last saw/accepted); unique (`cart_id`,`variant_id`) |
| `wishlist_items` | Signed-in wishlist (guest wishlists live in the browser) | `user_id`, `product_id`; unique (`user_id`,`product_id`) |

### Orders, payments, fulfilment
| Table | Purpose | Key columns / constraints |
|-------|---------|---------------------------|
| `orders` | One purchase | `reference` unique, `user_id` (nullable for guests), `guest_access_token_hash`, `email`, `phone`, `status`, `payment_status`, `currency`, `subtotal`, `discount_total`, `taxable_total`, `tax_total`, `shipping_total`, `rounding_adjustment`, `grand_total`, `coupon_code`, `shipping_address JSONB`, `billing_address JSONB`, `shipping_method JSONB`, `pricing_context JSONB` (rates + tax config used), `idempotency_key` unique, `terms_accepted_at`, `payment_expires_at`, `paid_at`, `cancelled_at`; CHECK `grand_total >= 0` |
| `order_items` | Immutable line snapshot | `order_id`, `product_id`, `variant_id` (kept for reference), `product_name`, `variant_label`, `sku`, `purity`, `image_url`, `quantity`, `unit_price`, `line_metal_value`, `line_wastage`, `line_making_charge`, `line_stone_value`, `line_other_charges`, `line_discount`, `line_taxable_value`, `line_tax`, `line_total`, `price_inputs JSONB` (rate id, rate, weights, making config) |
| `order_events` | Status timeline + audit trail per order | `order_id`, `kind`, `from_status`, `to_status`, `note`, `actor_type` ∈ {customer, admin, system, provider}, `actor_user_id`, `created_at` |
| `payment_attempts` | Each Razorpay order created for an order | `order_id`, `provider` ∈ {razorpay, simulator}, `provider_order_id` unique, `provider_payment_id` unique nullable, `amount_paise`, `currency`, `status` ∈ {created, authorized, captured, failed}, `method`, `error_code`, `error_description` |
| `payment_events` | Raw verified webhook events | `provider`, `event_id` unique, `event_type`, `payload JSONB`, `received_at`, `processed_at`, `processing_error` |
| `refunds` | Refund requests and results | `order_id`, `payment_attempt_id`, `provider_refund_id` unique nullable, `amount`, `status` ∈ {requested, pending, processed, failed}, `reason`, `requested_by` |
| `shipments` | Dispatch info | `order_id`, `carrier`, `tracking_number`, `tracking_url`, `status` ∈ {pending, shipped, delivered, returned}, `shipped_at`, `delivered_at` |
| `return_requests` | Returns / exchanges | `order_id`, `user_id`, `kind` ∈ {return, exchange}, `status` ∈ {requested, approved, rejected, received, refunded, closed}, `reason`, `items JSONB`, `admin_note` |

## Important indexes

* `products (status, category_id)`, `products (published_at DESC)`, GIN on `products.search_vector`.
* `product_variants (product_id)`, unique `product_variants (sku)`.
* `orders (user_id, created_at DESC)`, `orders (status, created_at DESC)`, `orders (payment_status)`,
  `orders (payment_expires_at) WHERE status = 'pending_payment'`.
* `inventory_reservations (status, expires_at)`.
* `gold_rates (purity, effective_from DESC)`.
* `email_outbox (status, created_at)`, `audit_logs (entity_type, entity_id)`, `audit_logs (created_at DESC)`.
